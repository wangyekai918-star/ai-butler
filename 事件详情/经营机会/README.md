## 页面结构

1. **事件信息**：事件信息使用通栏字段宫格，事件描述保留在宫格底部；AI分析结论位于宫格下方，独占一整行，与宫格间距 8px。标题统一为「AI分析结论」，沿用 AI 渐变样式。内容宽度达到 720px 时字段为两行四列，窄窗口为两列；分析结论始终放在下方。
2. **分析过程**：第一行横向排列机会依据、电站运营表现、历史效果复核、未来充电量预测四张同高卡片；第二行左侧展示最终机会结论、右侧展示调价建议，宽度为 2:3。保持业务顺序，各卡片先说明判断再展示关键数据。卡片间距 8px，卡片组距外卡 12px。前四步在窄窗口保留 224px 最小卡宽并组内滚动；结果行内容宽度不足 710px 时上下排列。
3. **决策生成**：服务费分时段调整表、执行期间、执行方式、范围及调价目的。
4. **评估复盘**：评估状态、结果、评估次数、收益达成率、经营指标变化、趋势及 AI 复盘结论。与决策生成并排，间距 14px；窄窗口顺序排列。

保留已确认的 12px 外卡内边距、8px 内部模块间距、12px/18px 辅助说明，各分析卡片使用淡蓝渐变标题。分析过程纯白底，标题吸顶距 60px 顶栏保留 12px；灰底遮挡层避免圆角透出滚动内容。主要数值使用 Oswald，中文与单位分别排版。右侧生命周期支持点击定位及滚动高亮，仅导航高亮。

服务费收入是本事件主指标，使用绿色；充电量、充电用户使用灰色中性样式；AI 创造价值使用浅紫底。顶栏、左导航和返回维持静态外观，不执行外部业务操作。新 Demo 顶栏使用示例身份文案。

## 数据与来源

- 产品原型：经营机会_五步机会评估版_v2.html（本地原型，不随仓库分发）。
- 事件详情 PRD（内部需求文档）：2026-09-14 读取，依据 3.2、4.2、5.1、6.2。
- [项目 UI 风格规范](../../AI管家UI风格规范.md)，以及前两个 Demo 的用户已确认样式。

以下口径需要开发对接业务数据时保留区分：

- **机会持续时间**：原型最终结论写 7 天，但事件影响窗口、调价建议、决策均为 2026-08-21 至 2026-08-23。本 Demo 统一按明确时间窗口展示 **3 天**，该差异需产品确认。
- **感知信号与预测区分**：原型开头用“需求提升 43.8%”，五步依据实际给的是“周末热门倍率 143.8%”，未来预测另为“+5.6%”。事件描述改为陈述倍率和触发标准，避免把两种口径都表达为同一期间的预测结果。
- **预测缺失字段**：预测量 15,210 度、较正常基准 +5.6% 沿用原型；原型未给正常充电量基准值，因此展示“—”，不混用 PRD 其他示例的 14,620 度，也不反推或补造每日预测曲线。
- **调价建议**：当前 0.30 元/度、建议 +0.03 元/度、调整后 0.33 元/度，竞品主流区间 0.32 至 0.36 元/度。PRD 要求的“建议调价范围”在本事件原型中缺失，保留 null 并展示“—”。
- **默认时段**：只展示原型给定的一行全天统一价。数据结构仍支持多个时段；超过 3.5 行内部滚动、底部渐变，滚到底部后遮罩消失。
- **策略状态**：原型决策写“已生成”而复盘为“已复盘”。默认页同步为决策“已完成”、事件“已复盘”。原型未给同步通知动作，隐藏该字段，没有带入经营风险通知。
- **复盘指标**：原型 -673 度、-25 人是变化值，不能作为累计实际量。界面明确标记为“充电量变化”“充电用户变化”，对应 -2.2%、-1.8%；服务费收入变化 +7.5%；AI 创造价值 +689 元。累计充电量、累计用户数和实际服务费金额须由业务接口提供，本 Demo 不反推。
- **趋势图**：原型只有静态 SVG，没有结构化日评估数据。本 Demo 保留其坐标对应的指数曲线，并显式标注“累计效果指数（示意）”。每个指数由 `100 + (152 - SVG_Y) / 5` 对应得到；日期保留原型 08/21、08/21、08/22、08/22、08/23、08/24，不补造具体时刻。该图与上方经营变化值不作数值联算。正式已复盘页面按 PRD 应接入每日累计评估节点，并统一基准、时间与指标口径；不能把此图示意点当作真实业务数据。
- **AI 复盘结论**：按原型“优”、收益达成率 105.6% 和经营变化值，结合 PRD 6.2 复盘结论模板生成。

## 状态与数据入口

`opportunity-analysis-data`：五步数据及 `constitutesOpportunity`、`eventSummary`、`advice`。各步状态支持 `passed / adjusted / failed / skipped / pending`。历史复核为 `skipped` 时，只显示“无需复核”和说明，隐藏次数等指标；0 次仅用于确实完成复核且结果为零。

`constitutesOpportunity` 为 false 时，不显示调价建议、决策生成、评估复盘及相应生命周期入口；未完成的分析应传入当前实际步骤数据和状态，不能保留成功示例结论。

`decision-review-data`：决策时段和复盘数据。复盘支持 `EVALUATING / PENDING_REVIEW / REVIEWED`，对应“阶段评估 / 最后一次阶段评估 / 复盘结果”。评级由业务提供，前端不自行计算优良差。缺失数值显示“—”，真实零值保留。

保留原型的 `?state=running` 入口：显示执行中、评估中、6 次评估，隐藏尚未给出的收益达成率，结论为“策略效果符合预期，建议继续执行”。该入口只演示状态，指标及趋势沿用同一原型，非另一组独立执行期间业务数据。

## 验证

已检查 1024、1280、1920px 布局，无页面横向溢出及指标裁切；标题横幅 44px、外卡内边距 12px、决策/复盘间距 14px、分析标题吸顶位置 72px。核验 SVG/PNG 资源、数字字体声明、价格与指标显示、生命周期点击高亮、控制台无页面错误。四过程与结果分行布局已在 1920px 和 1280px 下核验；前四步按顺序排列，结论与建议同排，窄窗保持可读宽度，无页面横向溢出。

内部用例覆盖机会不成立、无需复核、待复盘、零值、无趋势数据、多时段滚动及遮罩。前两个 Demo 的根目录运行文件经 SHA256 核验未变。
